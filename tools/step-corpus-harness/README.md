# step-corpus-harness

Meshes STEP files through the Plato library compiled to C# (`Ara3D.StepBrep`), the way `StepPlatoMesher.MeshFile` does, and times every step, edge and face. It is the corpus run's harness (`docs/plans/step-mesher-corpus-2026-10-19.md` in bim-open-toolkit) made permanent, for TKT-323's speed evaluation.

```
dotnet build tools/step-corpus-harness -c Release --artifacts-path artifacts/step-corpus-harness
step-corpus-harness time <file.step> <prefix> [--path host] [--parallel] [--warmup]
step-corpus-harness one <file.step> <out.json> [--path host|meshfile] [--parallel] [--warmup]
step-corpus-harness all <corpus folder> <out folder> <seconds per file> [flags as for one]
step-corpus-harness gallery <file.step | witness:Name[:x]> <out.glb> [--faces a,b,c] [--ring n] [--chordal x] [--parallel] [--warmup]
step-corpus-harness extract <file.step | witness:Name[:x]> <face,face,...> <out.plato> [--ring n] [--name Name] [--chordal x] [--parallel]
python tools/step-corpus-harness/gallery-page.py <folder of .glb and .json> [index.html]
```

- `time` writes `<prefix>.edges.csv` (curve kind, the surface kinds of the faces that cite the edge, segment count, milliseconds), `<prefix>.faces.csv` (surface kind, loop and edge counts, whether every edge is a line, triangle count, the branch taken, milliseconds per stage of layer 5's `MeshRegionOnce`) and `<prefix>.summary.json` (step totals including `RefineMs`, failures, and a digest of the assembled mesh).
- `one` writes the summary only. `--path meshfile` calls `StepPlatoMesher.MeshFile` itself; its digest equals the other paths', which checks the harness's stage-by-stage restatement.
- `all` runs `time` on every `.step` and `.stp` file under the folder, each in its own process killed after the limit, so the out folder holds every file's edge and face tables and summary (the per-surface-kind counts of a corpus report come from the face tables), and writes `all.csv` with the last stage line each file printed.
- `gallery` writes one model as a GLB for the gallery page (`docs/plans/step-mesher-gallery.md` in bim-open-toolkit): every meshed face as triangles coloured by surface kind (quads split), every discretized edge as a line, and the edges of every unmeshed face as red lines, with `<out>.json` beside it (counts, time per stage, the check, the slowest and most-edged faces, every unmeshed face with its branch and message). `witness:Name` meshes the library's `Witness_Name()` model, `witness:Name:0.3` the overload taking one Number; `--faces` with `--ring` keeps a close-up of named faces and their neighbours; `--chordal` replaces the host's chordal bound (a witness is one unit across, so 0.01). `gallery-page.py` turns a folder of those into the page, its cases listed in the script.
- `--path host`, the default, is the host's own path timed per row: `StepPlatoTables.Of` (layer 4's in-range flag, edge-face table and two-edge-loop flags and layer 8's arena flag, once per model, TKT-402), then the host's `Discretized` per edge and `IsDiscretized` and `MeshFace` per face. Every mode then runs the host's refinement loop on blocking requests (`StepPlatoMesher.Refined`, as `MeshFile` does; `refine_ms` in the summary, one clock for the loop): the edges it refined and the faces it meshed again carry their final discretization and outcome in the tables, a face's path reads `refined`, and their times stay the first pass's. The summary carries a `MeshCheck` (boundary, non-manifold and misoriented edge counts of the assembled mesh) beside the digest.
- Every mode checks the version 1 mesh contract on each face (`ContractCheck`, TKT-432) from the face meshes and the surfaces alone, independently of the library's own checks: the surface at seven sample points of each element's parameter triangle against the flat element (both diagonal splits of a quad), allowed the chordal bound plus the model's length tolerance plus the largest distance between a corner and the surface at its parameter point (the file's edge-to-surface gap); each element's normal against the face normal at its parameter centroid; no zero-area element; every face meshed or explained by a diagnostic. The verdict ends the time mode's last line (so `all.csv` carries it), goes into the summary and the gallery JSON, and `time` writes the failing faces to `<prefix>.contract.csv`. The bump solid at 0.3 (TKT-415) breaks it; the unit box and cylinder pass.
- `extract` writes faces of a file's prepared model as a Plato witness (TKT-439): `Witness_<Name>(_: BrepModel): BrepModel` in a library block of its own, holding those faces and every loop, edge, vertex, curve, pcurve and surface they reach, renumbered, with closure marks whose subject is kept, one open shell in a shell-set body, and the source's tolerances and unit (`SubModel`, by reflection over the generated types, so new fields and cases are followed). `--ring n` adds the faces sharing an edge, n deep: an edge's segment count reads the surfaces of every face citing it, so a face may mesh differently without its neighbours. Before writing, both models are meshed the host's way and each named face's branch and mesh digest are compared; the result is in the file's header and the exit code (0 when every face reproduces). The values are written by `PlatoLiteral` in round-trip form. Put the file in a staging folder and state the contract over it in a law, as `sandbox/step-mesh-staging/v1-reliability/corpus-witnesses.laws.plato` in bim-open-toolkit does.
- `--parallel` runs the edge and face rows with `Parallel.For`, as `MeshFile` does since TKT-403; without it the rows run in index order, which is the sequential witness for the host's parallel digest. Each row still catches its own exception. `--warmup` meshes the file once first, so the timings leave out JIT compilation.

The library must be generated from the current Plato library first (`tools/regen-step-brep.ps1`). The project is not in `BimOpenData.sln`.
